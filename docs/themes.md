# Themes

A theme is a folder with a `config.json` and, optionally, a `wallpaper.jpg`. Pushing one changes the launcher's
dock, layout and look on the TV without rebuilding the APK: the launcher reads `config.json` as an overlay over its
built-in `config.xml` the next time it starts. Choices made in Launcher settings take priority until the theme is
pushed again, which clears them (so does **Restore from file**).

Two themes ship:

| Folder | What |
|---|---|
| [`themes/default/`](../themes/default/) | The launcher's built-in values as a `config.json`: every key the launcher reads, with the value `config.xml` gives it (generated from `Config`'s reads; black background, a four-app dock row, the full-screen settings page). Pushing it is a reset in all but name; deleting the theme folder on the TV is the other. |
| [`themes/frosted/`](../themes/frosted/) | The owner's Mi TV 4A look: six uniform rows over a pre-blurred slate wallpaper, the settings side panel, the Trakt carousel, the All apps grid, the two-line date and the system bars on. `screenshot.jpg` is the fork's and is retaken in Phase 6. |

Push a theme with `tools/dev/push_theme.py themes/<name>` (plain `adb`, a Phase 1 stand-in) until the setup tool
replaces it in Phase 5: it writes the files through `content://com.itsluminous.verysmarttv.theme/<file>`, bumps
`theme_revision` and restarts Home. The provider accepts exactly three names, `config.json`, `wallpaper.jpg` and
`theme_revision`; the fork's `wallpapers/` collection went with the rotation (ADR-008).

## Keys

Every key is optional; a missing key keeps the value from `config.xml`, an unknown or wrongly typed key is ignored,
and a file that does not parse is ignored as a whole, so a theme can never break Home. A key of a feature this
launcher dropped (`festival`, `seasonal_skin`, `festival_until`, `greeting`, `accent_color`, `game_day`,
`race_calendar`, `sky_intensity`, `latitude`, `longitude`, `wallpaper_rotation_minutes`, `wallpaper_order`,
`wallpaper_moods`, `wallpaper_captions`, `shamsi_date`, `lunar_date`, `lunar_utc_offset`, `show_stats`) is ignored
with one `VerySmartTV.Config` log line each, so a theme written for the fork still loads (DESIGN.md §6, ADR-008).

`ThemeKeysTest` (Phase 3, DESIGN.md §11) will hold this table and `Config` to each other.

| Key | Type | Meaning |
|---|---|---|
| `dock_apps` | list of package names | The dock row, in order; missing apps are skipped |
| `fill_dock` | bool | Fill the dock slots `dock_apps` leaves free with the first grid apps (true by default); false leaves them empty |
| `hidden_apps` | list of package names | Never shown as tiles |
| `live_tv_package`, `live_tv_action` | string | The Live TV app and, if it has no leanback entry, the action to start it with |
| `live_tv_input_id` | string | Live TV source for the Inputs menu: an exact system tuner ID opens its channel collection. The special value `content://android.media.tv/channel` opens the stock launcher's root channel URI on Xiaomi MiTV-MSSP1. Empty keeps automatic selection. Missing input or unsupported collection falls back to the app's normal launch. |
| `source_panel_service`, `source_panel_action` | string | The TV's own source panel, for sets with no TvInputManager: a service, or an activity (BYINTEK U4). Without a Live TV app, the Inputs pill opens it directly |
| `source_panel_extra` | `"name=value"` | One int extra sent with the source panel (Coocaa OS: `control_center_command=100`) |
| `coocaa_sources` | bool | Coocaa OS (Skyworth, China): list the sources from `com.skyworth.tv` in the Inputs menu, ahead of the source panel |
| `launch_actions` | list of `"package=action"` | Tiles and `top_bar_apps` buttons that open a screen of the app instead of its start screen; an action that no longer resolves opens the app normally (MagentaTV's guide: `com.telekom.onetv.tv.pl=com.telekom.onetv.tv.pl.action.PROGRAM_GUIDE`); `"package=input:<input id>"` makes a tile switch to that TV input instead (ids from `dumpsys tv_input`), e.g. `com.mediatek.wwtv.tvcenter=input:com.mediatek.tvinput/.hdmi.HDMIInputService/HW5`; `"package=view:uri"` opens that URI in the package instead (Bbox TV's live channels: `fr.bouyguestelecom.tv.bbui=view:bbox://live`) |
| `app_labels` | list of `"package=Name"` | A tile's name instead of the app's own (MagentaTV as `com.telekom.onetv.tv.pl=TV`) |
| `app_banners` | list of `"package=banner_name"` | A tile's artwork from a `banner_*` drawable bundled with the launcher (`banner_tv`: magenta with the Live TV glyph) |
| `input_action` | string | Action sent with an HDMI/AV row's channel URI when nothing handles the standard `VIEW` (XGIMI: `com.xgimi.action.hdmiPlayer`). Only a handler-less set gets here; any app that claims the channel MIME type takes the row instead, so check with `query-activities`. Written as `package/.Activity` it names the vendor's own source picker, which every row starts first (Redmi X65, MiTV-NSOP0: `com.xiaomi.mitv.tvplayer/.ExternalSourceActivity`) |
| `input_uri_scheme` | string | Scheme an HDMI/AV row's passthrough URI is sent with instead of `content://`, with no MIME type (YaOS: `live-tv`, which its source player answers) |
| `input_sources` | list | Vendor source numbers for the Inputs menu, `HW<n>=<number>` by the input id's last part; a mapped input opens by sending `input_action` with the number as the int extra `input`, and `HW<n>=-` leaves a port the set doesn't have out of the menu. Xiaomi/Redmi China firmware: the `redmi-mitv-mftp0` preset |
| `columns` | 1 to 8 | Tiles per row; tiles shrink to fit from 5 up |
| `rows_below_dock` | 0 to 3 | Grid rows left visible under the dock; tiles shrink if the dock, its title and that many rows would not fit the screen height |
| `hero_feed_interval` | 3 to 120 | Seconds the `hero_feed` carousel stays on one item (`8` by default) |
| `row_gap` | 29 to 90 | Space from the bottom of a tile to the top of the tile in the next row, in dp, in the `dock_row` layout (`45` by default, the layout's own: 8dp above and below each item, a 7dp gap and the 22dp name). The focused tile's name is centred in that gap at every value (measured from the tile's unscaled bottom; the focus zoom's growth and the `advanced_effects` lift cancel out), long names end in an ellipsis, and the item's padding takes what is left; the dock's 12dp offset below its row shrinks in the same proportion. `32` puts the rows about 30% closer |
| `hero_height` | 0, or 50 to 130 | Height of the top shelf, the room above the dock line where the app's name or the `hero_feed` carousel sits, as a percent of the layout's own. `0`, the default, is auto: 100 while the carousel is on (`hero_feed`, as the Trakt recommendations row in Launcher settings leaves it) and 80 without it, where the app's name alone needs less room. Below 100 the dock and the rows under it move up in proportion and more rows show; the shelf's text and spacing scale with it (the carousel's 36sp title reads 30sp at 80 and 24sp at 60, the app's name and the cinematic lines in the same proportion, the gaps between the lines too), the carousel keeps two synopsis lines at 80 and below and one line with no rating chips at 60 and below, its backdrop shrinks with the shelf, the first row never comes up under the shelf's dots (the resting line stays at least the shelf's measured height under the header), and the header with the clock and the pills never moves. Above 100 the dock sits lower and the rows under it run off the bottom until you press Down. The **Hero banner height** row in Launcher settings (Compact 60, Short 80, Normal 100, Tall 120) overrides this on the TV; the row and its picker show the height in force, the one this key resolves to until a choice is saved ("Short (80%)" say), and a height outside the four joins the picker as its own row ("70%") |
| `date_two_lines` | bool | The date beside the clock on two lines, the day of the week over the day and month (`WEDNESDAY` over `4 NOVEMBER`, each from the TV's language's own date pattern, so `NOVEMBER 4` in the US), in the date's caps and tracking, the block centred on the clock's height; the line between the clock and the date stays, and the header keeps its height. Not applied with `date_below_clock`, whose extra line would push the header down (`false` by default) |
| `widgets` | bool | The RAM and Storage bars right of the date: two rows, a label at the left and `N GB free` at the right over a thin track bar, in the pills' frosted finish (DESIGN.md §9.1). Read every 5 seconds only while Home is on screen; nothing is read while it is off. The **System bars** row in Launcher settings (On, Off; it shows the state this key gives until a choice is saved) overrides this key on the TV. A theme from before the change may still carry the old array of chip names (`["memory", "cpu", "storage"]`): it reads as `true` when it names anything and `false` when empty, and the launcher logs the migration once. `false` by default. **Phase 1 state:** the key is read and the row toggles it; the bars themselves land in Phase 3, so nothing is drawn yet |
| `dock_title` | bool | The focused dock app's name in large type above the dock (`true`); `false` keeps only the glow |
| `dock_row` | bool | The dock as its own row with a band (`true`); `false` makes the dock apps the first tiles of one plain grid |
| `reorder_button` | bool | A reorder button in the top bar (`false` by default); reordering is always in the Settings button's long-press menu |
| `show_network_pill` | bool | The Wi-Fi/Ethernet pill in the top bar (`true` by default); `false` hides it |
| `top_bar_apps` | list of package names | Apps shown as round buttons with their own logo in the top bar, left of the network pill; they leave the grid |
| `show_inputs_pill` | bool | The Inputs pill in the top bar, shown when the TV has inputs (`true` by default); `false` hides it, and with `top_menu` it also leaves Inputs out of the gear's menu (streamers with no HDMI input, such as the Chromecast with Google TV); what the remote's Input button does is unchanged |
| `icon_only_buttons` | bool | Wi-Fi and Settings as round icon buttons; Inputs keeps its label. The VPN badge is drawn in the Wi-Fi pill's label, so with `wifi_label_width` at 0 it goes with the label: add `vpn_pill` to keep the VPN state on screen (`false` by default) |
| `icon_only_inputs` | bool | The Inputs pill as a round icon button too, its label kept as the TalkBack description (`false` by default). Works with or without `icon_only_buttons` |
| `pill_labels_on_focus` | bool | With `icon_only_buttons` or `icon_only_inputs`: the focused round pill grows to show its name (Inputs, the network, Library, Settings) and shrinks back when focus leaves; the names stay as TalkBack descriptions either way (`false` by default) |
| `tv_settings_first` | bool | Launcher settings opens with **TV system settings** as its first, focused row instead of its last, for a Settings click that `launcher_settings_button` sends to that page (`false` by default) |
| `settings_panel` | bool | Launcher settings as a side panel over Home in the style of the TV's own Settings: TV system settings first, then the launcher's rows with their current value; a row with several values opens a list in the same panel and Back returns. With `launcher_settings_button` the Settings pill keeps its gear (`false` by default: the full-screen page) |
| `shelf_every_row` | bool | Every row behaves like the dock: focusing a tile in a lower row scrolls that row up to the dock's place under the shelf, the rows above slide out, and the shelf names the focused app in large type with its colour; tiles carry no names, and the dock menu items are left out; in the settings panel the **Rows below dock** row reads **Rows shown below the first row**, since no row is the dock. Needs `dock_row` (`false` by default) |
| `uniform_rows` | bool | No dock: the grid is one flat order laid out `columns` per row, the first row included, so 7 per row puts 7 in the top row. The first row has no band, empty slots or gap of its own: `fill_dock` reads true, `rows_below_dock` 0 and `shelf_every_row` on while it is set, so every row scrolls to the same line, the shelf's bottom at `hero_height`, and the rows fill downward from it (Down scrolls). `dock_apps` only seeds the head of the order until the owner reorders, and keys the saved order as before; `dock_band`, `dock_opacity`, `dock_glass` and `dock_even_padding` do nothing. Launcher settings leaves out **Rows below dock** and **Dock band opacity**. Needs `dock_row`; `single_row` wins over it (`false` by default) |
| `hero_feed` | bool | The top shelf is a carousel of the titles the Trakt shelf app offers (`:traktshelf`, read through its content provider, [providers.md](providers.md)): backdrop faded into the wallpaper, title, year, a synopsis of up to three lines, IMDb / RT / Trakt chips and one dot per item, one item every `hero_feed_interval` seconds. It owns the shelf while that app has items: moving between tiles leaves it alone, and the focused app's name shows under its tile instead (the dock's too; with `shelf_every_row` the rows still scroll up to the dock's line, but the shelf no longer names the app). Up from the dock focuses the carousel, Left/Right move it, OK opens the title in that app, Down or Back goes back to the tile. Without that app installed, or with nothing in it, the shelf is as before. Needs `dock_row` (`false` by default). The **Trakt recommendations** row in Launcher settings (On, Off; it shows the state this key gives until a choice is saved) overrides this key on the TV: Off is exactly `false`, whatever the theme says, and the row says when the Trakt shelf app is not installed |
| `top_menu` | bool | Inputs, Wi-Fi and Settings folded into one round gear, centred on the header: OK drops a menu with the three plus Reorder apps, hold OK keeps the launcher menu (`false` by default) |
| `launcher_settings_button` | bool | Make the header Settings action open Launcher settings directly with a matching 22dp home icon; also changes the Settings row when `top_menu` is on. Hold OK keeps module-card and ordering tools. The settings page includes Reorder apps and TV settings (`false` by default) |
| `wifi_status_color` | bool | The Wi-Fi pill's icon green while the TV is online, white while it is not (`false` by default) |
| `wifi_status_warnings` | bool | With `wifi_status_color`, the icon orange while connected without internet (a captive portal waiting for its login page) and red while offline, instead of white (`false` by default) |
| `wifi_label_width` | 0 to 300 | With `icon_only_buttons`, keep the network name on the Wi-Fi pill up to this width in dp, cut with an ellipsis; 0 leaves only the icon |
| `library_button` | bool | The app library as a round button in the top bar, beside Settings; needs `app_library`. Closing the library returns to it |
| `show_library_pill` | bool | The App library pill after the last Home row (`true` by default); `false` hides it while `library_button` is on, so the top-bar button stays the way in and Down from the last row stays put, as with `app_library` off |
| `always_show_names` | bool | Names under every tile, dimmed until focused, the dock included (its band grows to hold them); `false` by default shows only the focused tile's name |
| `wallpaper_true_color` | bool | Decode wallpapers in 32-bit colour (8 MB at 1080p) instead of RGB_565 (4 MB), which bands dark gradients such as a night sky; for TVs with 2 GB or more (`false` by default) |
| `app_library` | bool | An App library pill after the last Home row: every installed app, add one to Home or take it off (`false` by default). The choices stay on the TV when a theme is pushed or reset |
| `uniform_tiles` | bool | Each app tile is its icon on a card tinted from that icon, with the name only under the focused tile, instead of the app's own banner (`false` by default) |
| `icon_tiles` | list of package names, `config.xml` only | Apps drawn from their icon and name instead of their banner, for banners that crop badly; empty by default. Not read from a theme |
| `app_library_selection` | bool | OK toggles Home checkmarks in the library; checked apps first, both groups alphabetized. Hiding keeps focus on the adjacent next app (previous at the end). Requires `app_library`; `false` preserves the standard open/long-press behavior |
| `library_ok_opens` | bool | OK opens every app in the library, not only the ones on Home, for a library that holds the apps `hidden_apps` keeps off Home; holding OK still offers Add to Home, and cards drop their "Add to Home" line. Requires `app_library`; `app_library_selection` wins when both are on; `false` by default |
| `library_columns` | 0 to 8 | The All apps popup as a vertical grid of compact cards (a 46dp icon, a one-line name) with that many columns, 2 to 8, and three rows on screen, scrolling down; Up/Down move between rows and the edges stay fenced. `0` (the default) keeps the one horizontal row, and `1` is read as `0` |
| `library_apps` | list of package names | Packages pre-seeded into the App library's "added" set at startup (config.xml `library_apps`, or a theme's `config.json`). They show on Home as if the owner had added them in the App library UI, and stay removable there (a removed one stays hidden); empty (off) by default |
| `library_excluded_apps` | list of package names | Packages the App library catalogue never offers, even with `app_library` on. Different from `hidden_apps`, which only keeps a package off Home while still listing it in the catalogue; empty (off) by default |
| `date_below_clock` | bool | The date on its own line under the clock instead of beside it, for a top bar whose pills leave the date too little room (`false` by default) |
| `locale` | string | The language the launcher shows itself in, as a language tag (`"vi"`, `"pt-BR"`, `"ar-EG-u-nu-latn"` for Arabic with Western digits), instead of the TV's: for firmware with no menu entry for a language the launcher speaks (a China-market Xiaomi offers Chinese and English only). Empty by default, which follows the TV |
| `greeting_name` | string | A name after the greeting, e.g. `"Mr. Trịnh"` for GOOD MORNING, MR. TRỊNH; empty for the greeting alone |
| `show_greeting` | bool | The greeting above the clock (`true` by default); `false` hides it |
| `header_white` | bool | The date and the line between the clock and the date in the clock's full white instead of dimmed (`false` by default) |
| `module_cards` | bool | Look for module cards and ask about them (`true`); `false` turns the feature off |
| `reduced_motion` | bool | Calmer motion for weak GPUs: the highlight slides without bouncing and settles within 5 frames, every animation lasts 90 ms or less, names, the top shelf, the glow and the highlight appear instead of fading, and there is no tile entrance (`false` by default) |
| `boot_to_live_tv` | bool | Open the Live TV app (`live_tv_package`) on the first Home after the TV starts, once per boot |
| `open_on_start_choice` | bool | `true` adds an **Open on start** row to Launcher settings: pick an app on the TV, and the first Home after each boot opens it instead (once per boot; `boot_to_live_tv` wins when both are set; an app that is gone or disabled leaves Home on screen). Off by default |
| `open_on_start_network_wait` | 0 to 600 | Seconds the first Home after the TV starts waits for a working internet connection before it opens the `boot_to_live_tv` or Open on start app. A streaming app opened before the network is back shows an error, and after a power cut Wi-Fi can take minutes, as the router starts again too. Home stays on screen meanwhile, and leaving Home cancels the opening. `0`, the default, opens the app at once |
| `open_on_start_on_wake` | bool | With `open_on_start_choice`, the picked app also opens each time the screen comes back on, for TVs whose remote powers them into a light sleep with no boot. It opens over whatever was in front, an HDMI input included, and `open_on_start_network_wait` applies. Off by default |
| `focus_overshoot` | bool | The highlight and the focused tile swing past their target before settling (`true` by default); `false` glides straight there with smooth scrolling |
| `vpn_app` | string | App the network pill opens when a VPN is configured; also shows a red "VPN off" badge while no VPN is up |
| `vpn_pill` | bool | The VPN as its own pill after the network pill instead of a badge inside it: solid green while a VPN is up, solid red "VPN off" while none is and `vpn_app` is installed, hidden otherwise. Pressing it opens `vpn_app` (without it, the App library, or VPN settings with `app_library` off); it keeps its label with `icon_only_buttons`; the network pill then opens Wi-Fi settings. Ignored with `top_menu`. A VPN app's kill switch holds a VPN up while the app says disconnected, so the pill stays green then (`false` by default) |
| `icon_only_vpn` | bool | With `vpn_pill`, the VPN pill as a round icon button too, matching `icon_only_buttons`: an open lock on the plain glass button while no VPN is up, the closed lock in a green outline while one is, solid green only while focused, like the pill; "VPN" / "VPN off" become its TalkBack description (`false` by default) |
| `animations` | bool | Basic focus, glass, title and tile entrance motion; true by default. The **Animations** row in Launcher settings switches it on the TV, and `advanced_effects` with it |
| `advanced_effects` | bool | Optional lifted tile, icon zoom, smooth ambient colour and app opening effects; false by default. Only in force while animations are on: the **Animations** row Off is still, On runs these when the theme sets them, and there is no separate Advanced effects row or saved choice (an `advanced_effects` choice an older launcher saved is dropped on load and on restore) |
| `show_home_settings_shortcut` | bool | Keep the optional Default-home tile visible when the TV has a home picker; false by default |
| `handle_view_inputs` | bool | Answer the system input switcher (`VIEW_INPUTS`, what the remote's Input button becomes) with the Inputs menu, for sets whose stock launcher was its only handler (Hisense huangshan); `false` by default so a TV with its own input picker never gets a chooser |
| `background_color` | `#RRGGBB` | Colour behind everything; black by default |
| `wallpaper` | bool | Show the theme's `wallpaper.jpg` (`true`), or draw only `background_color` (`false`) |
| `wallpaper_dim` | 0 to 90 | Black painted into the wallpaper once, in percent; 0 by default |
| `dock_opacity` | 30 to 100 | Opacity of the dock's band, in percent, so a wallpaper shows through it; 100 by default (the cinematic shelf keeps its own translucent band). Launcher settings on the TV offers 100, 70, 50 or 30, which wins until the next theme push or Follow theme |
| `tile_menu` | bool | Hold OK or press the remote's Menu key on a tile to open a small menu: Move, Remove from Home (with `app_library`) and App info. `true` by default since launcher 3.3; `false` keeps holding OK as a shortcut to the app's App info page and leaves Menu unchanged |
| `settings_key_scancodes` | list, `config.xml` only | The same buttons by Linux scancode, for `HomeKeyService` (enabled by the setup tool); the Xiaomi/Fengmi projector remote's gear is scan 384. `Config.java` reads `settings_key_keycodes` out of a theme but never this one, so a `config.json` that sets it is dropped - it belongs in `config.xml` before the build. | `settings_key_keycodes` | list of keycodes | Remote buttons that open Settings, for `HomeKeyService` (TCL Google TV gear: `[83]`) |
| `settings_key_panel` | bool | Those buttons open a small quick settings panel (TV settings, Display, Network, Apps, Launcher settings) instead of the TV's Settings |
| `settings_fallback_components` | list, `config.xml` only | Vendor screens tried in order when nothing usable answers the standard Settings action (Xiaomi China, TCL/FFALCON, and Fire OS, where the real menu lives in its launcher), each as `package/activity`; the first one whose package is installed wins, and when none is, the standard intent is sent anyway and may open nothing. | `restore_key_services` | bool | After a force stop of the launcher, Home puts the remote's accessibility helpers (`HomeKeyService`, `InputKeyService`) back on the enabled list; needs the `WRITE_SECURE_SETTINGS` grant after every install (the setup tool grants it), since an install without it takes the grant back. | `input_key_keycodes` | list of keycodes | More remote buttons that open the input switcher, for `InputKeyService` (`KEYCODE_TV` and `KEYCODE_TV_INPUT` always do) |
| `app_keys` | list of strings | Remote buttons that open an app, as `"190:com.google.android.youtube.tv"` or `"KEYCODE_BUTTON_3:com.google.android.youtube.tv"`, or by scancode as `"scan:490:com.wbd.hbomax"` for remotes that share one keycode between app buttons (Sony BRAVIA), for `InputKeyService` or `HomeKeyService`. `"input:<input id>"` in place of the package switches to a TV input instead, e.g. `"scan:227:input:com.tcl.tvinput/.passthroughinput.TvPassThroughService/HW1413744640"` for an HDMI port (ids from `dumpsys tv_input`). `"inputs"` in place of the package opens the Inputs menu, for a remote whose source button sends a key Android does not map, e.g. `"scan:365:inputs"` (TCL 65C745). | `power_on_home` | bool | For firmware that opens the Live TV app (`live_tv_package`) by itself at every power-on (Changhong / Homwee): until the first key press after boot or screen-on, that Live TV window is sent back to Home (`HomeKeyService`). | `home_long_press_home` | bool | Every Home press opens Home, a held one too. Android turns a Home press held past 400 ms into ALL_APPS for the system-image launcher, which nothing answers once the stock launcher is disabled, so a firm press on a slow remote did nothing (Philips TPM191E, Android 12, where `long_press_timeout` does not move that limit). Needs `key_filter` (`HomeKeyService`), so held keys such as Volume Up/Down stop repeating, confirmed on that Philips; single presses still step. Off by default |
| `power_on_home_always` | bool | Home at every power-on, whatever the TV put in front: the last HDMI input, Live TV or an app, for TVs that come back to the last source (Philips). Unlike `power_on_home`, it does not wait for a window to show: the Home screen comes up about a second after the screen turns on (`HomeKeyService`). A key pressed before that wins. Ignored with `boot_to_live_tv`, or with an Open on start app. Off by default |
| `inputs_connected_only` | bool | The Inputs list shows only HDMI ports and CEC devices that report connected; empty ports, the AV jacks and devices asleep in standby fold behind a "More inputs" row that expands them. Some TVs (TCL) report an empty HDMI port as connected-standby, the same state a sleeping device has, so a device in standby is folded too. An HDMI row whose state the TV cannot be trusted with stays (`false` by default) |
| `inputs_cec_state_only` | bool | Only CEC device rows in the Inputs list show a connection state ("Steam Deck · HDMI 1", Connected); bare HDMI ports show none. For TVs that put port states on the wrong port: TCL UnionTV (Android 9) reports its empty HDMI 1 as connected and a device on HDMI 2 nowhere, while its CEC device list stays right. A device without CEC shows no state (`false` by default) |
| `clock_format` | `12`, `24` or `system` | The launcher's clocks (Home and the clock screensaver) in 12- or 24-hour time whatever the TV is set to; `system` (the default) follows the TV. Launcher settings' Clock row sets it too |
| `home_idle_clock_minutes` | 0 to 1440 | Minutes Home may sit untouched before it shows the clock screensaver (a thin clock and date drifting over a slow glow, as the system "Clock" screensaver does). Any key returns to Home. It starts only from Home, never over Live TV or an app; 0 is off (default) |
| `back_opens_clock` | bool | Back on the Home screen opens the clock screensaver (the same screen as `home_idle_clock_minutes`) instead of doing nothing. Back inside apps, Settings and the App library is unchanged; any key leaves the clock for Home. `false` by default |
| `clock_wallpaper` | bool | The clock screensaver over Home's wallpaper instead of black with a coloured glow; the clock still moves every minute (`false` by default) |
| `clock_wallpaper_dim` | 0 to 90 | How dark that wallpaper is behind the clock, in percent (50 by default) |
| `clock_glow` | bool | The clock screensaver's coloured glow (`true` by default); `false` leaves the moving clock on plain black, e.g. for an OLED |
| `glow_style` | string | Shape of the glow behind the focused app, in its colour: `radial` (default) or `horizon`, the colour washing down from the top edge to black; the cinematic shelf keeps its own |
| `glass_style` | string | Look of the focus highlight: `glass` (default: a translucent slab with a bright top sheen, a crisp rim and a faint outer glow), `rim` (the crisp rim alone, no sheen, fill or glow, for a quiet focus over a wallpaper) or `halo` (the rim with a lighter outer glow) |
| `cinematic_home` | bool | Cinematic top shelf: the focused dock app's artwork, softened, fills the top of the screen in its colour, with a larger name, "Last opened" (apps opened from Home), dock position dots, a focus glow in the app's colour and a translucent dock band; off by default |
| `cinematic_dots` | bool | With `cinematic_home`, the dock position dots under the app's name (`true` by default); `false` leaves them out |
| `cinematic_white_focus` | bool | With `cinematic_home`, the focus highlight stays white on the dock instead of taking the focused app's colour (`false` by default); `app_glow` still colours every tile |
| `cinematic_scrim` | 0 to 100 | With `cinematic_home`, the strength of the dark scrim behind the shelf's name (`100` by default); lower lets a wallpaper show through |
| `cinematic_art` | 0 to 100 | With `cinematic_home`, the opacity of the focused app's softened artwork (`50` by default); `0` leaves the wallpaper uncovered |
| `dock_even_padding` | bool | The dock band's padding equals the gap between its tiles on all four sides, as far as the grid's edges leave room (`false` by default) |
| `dock_glass` | bool | The dock band as light frosted glass like the top bar's pills (`false` by default); suits a wallpaper, where the solid band reads as a dark slab |
| `dock_band` | bool | Draw the dock band and its edge (`true` by default); `false` leaves the tiles floating on the wallpaper with no band, border or dark slab |
| `single_row` | bool | Every app in the dock's row, the dock apps first, scrolling sideways; no grid below (`false` by default; needs `dock_row`) |
| `dock_band_all` | bool | With `single_row`, the band runs behind every app in the row, not only the dock apps (`false` by default) |
| `ambient_glow` | bool | The glow behind the dock in the focused app's colour (`true` by default); `false` keeps only `background_color` or the wallpaper, e.g. for a calm photo background |
| `glow_snap` | bool | The ambient glow takes the next app's colour in one frame instead of dimming and fading back in. Each frame of the fade repaints the whole screen, so on a slow GPU (a Mali-G52 on a Xiaomi MiTV-MOEU0) it cut the late frames on Home from 60% to 27%. `false` by default |
| `app_glow` | bool | The focus highlight glows in the focused app's colour on every tile, as `cinematic_home` does for the dock (`false` by default) |
| `fade_rows` | bool | The rows fade out as they scroll up under the clock instead of being cut off at a hard line; the wallpaper shows through. The grid then draws into a hardware layer (about 6 MB of graphics memory at 1080p) (`false` by default) |

The three rows marked `config.xml` only (`icon_tiles`, `settings_key_scancodes`, `settings_fallback_components`)
are build-time: a theme that sets them is ignored for those keys.

## Reduced motion

`reduced_motion` is for TVs whose GPU drops frames on the default springs: the highlight slides without bouncing,
every animation is 90 ms or shorter, and nothing fades. `animations: false` goes further and turns the motion off
altogether; the **Animations** row in Launcher settings is the same switch on the TV.

## Adding a theme

A theme is one folder under `themes/` with a `config.json` of the keys above, an optional `wallpaper.jpg`
(1920×1080, pre-blurred for the frosted look; the launcher decodes it to the screen size and keeps one copy in GPU
memory) and a `screenshot.jpg` from a real TV. No addresses, network names or account names in any of the three:
`greeting_name` is the one key that holds a person's name, and the owner's theme leaves it empty.
